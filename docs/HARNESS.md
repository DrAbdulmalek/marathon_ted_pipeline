# Harness Engineering — الدليل الكامل

> **الفكرة الأساسية**: النموذج ليس المشكلة. المشكلة في **كيف** ندير النموذج.
> الـ Harness هو الطبقة التي تنظّم عمل الوكيل: التعليمات، الحالة،
> التحقق، النطاق، ودورة الحياة.
>
> هذا الدليل جزء من عقد `AGENTS.md` الملزم في هذا المستودع — يُقرأ معه عند كل جلسة.

## 1. لماذا Harness؟

### المشكلة

عندما يفشل وكيل ذكاء اصطناعي في مهمة، الحل الشائع: "استخدم نموذجاً أقوى".
لكن في كثير من الحالات:

- **الوكيل نسي السياق** ← لأن الذاكرة غير موجودة
- **الوكيل تجاوز خطوة تحقق** ← لأن البوابات غائبة
- **الوكيل اختلق مصادر** ← لأن القاعدة الصفرية غائبة
- **الوكيل كرر عملاً أُنجز** ← لأن الحالة غير مكتوبة

هذه **مشاكل بنيوية**، لا مشاكل نموذج. الحل: Harness.

### التعريف

**Harness** = طبقة تنظيمية بينك وبين الوكيل، تحدد:

| العنصر | يجيب عن السؤال |
|--------|----------------|
| **التعليمات** | ماذا يفعل؟ |
| **الحالة** | أين توقف؟ |
| **التحقق** | كيف نعرف أنه نجح؟ |
| **النطاق** | ما المسموح؟ ما الممنوع؟ |
| **دورة الحياة** | كيف يسلّم للجلسة التالية؟ |

## 2. المكونات الخمسة

### 2.1 التعليمات (Instructions)

**الملف**: `AGENTS.md` — يُقرأ في بداية كل جلسة، ويحتوي: نظرة عامة على المشروع،
القواعد الصفرية (غير قابلة للتفاوض)، بوابات التحقق، الأدوات المسموحة/الممنوعة،
وصيغة التقرير.

**قاعدة**: إن لم يكن في `AGENTS.md`، فهو غير ملزم.

### 2.2 الحالة (State)

**الملفات**: `feature_list.json` (ما المهام وما حالتها)، `progress.md` (ما حدث عبر
الزمن)، `session-handoff.md` (ما يحتاج الوكيل التالي معرفته).

**قاعدة**: لا تفترض أن الوكيل يعرف شيئاً. اكتبه.

### 2.3 التحقق (Verification)

**الملفات**: `init.sh` (بوابة الدخول — بداية الجلسة)، `scripts/verify.sh` (بوابة
الجودة — قبل الالتزام)، `scripts/session-handoff.py` (بوابة التسليم — نهاية الجلسة).

**قاعدة**: لا تقبل "يبدو صحيحاً". اقبل فقط مخرجاً خاماً.

### 2.4 النطاق (Scope)

**الموقع**: قسم في `AGENTS.md` — ما يشمله المشروع، ما لا يشمله، التبعيات.

**قاعدة**: الوكيل بلا نطاق = فوضى.

### 2.5 دورة الحياة (Lifecycle)

```
Resume → Advance → Handoff

1. Resume : ./init.sh ثم اقرأ AGENTS.md + session-handoff.md + ابحث في Mem0
2. Advance: اختر مهمة واحدة غير مكتملة → نفّذ → ./scripts/verify.sh → commit
3. Handoff: python3 scripts/session-handoff.py --note "..." --next "..."
            ثم اكتب progress.md وCommit
```

**قاعدة**: كل جلسة تُنتج ملف تسليم جديداً.

## 3. القواعد الصفرية (ملخص — النص الكامل في AGENTS.md)

1. **main لا يُلمَس مباشرة** — كل العمل على فروع `feat/*` أو `fix/*`، والدمج قرار المالك وحده عبر PR.
2. **كل ادعاء يحتاج مخرجاً خاماً** — ❌ "الاختبارات نجحت" / ✅ `pytest tests/ → 61 passed`.
3. **عند فشل بوابة → STOP** — لا "أصلح بسرعة"، لا "أكمل وأصلح لاحقاً".
4. **كل مرحلة ناجحة = commit مستقل + وسم `stage-N-complete`**.
5. **ممنوعات مطلقة**: `force-push`، حذف فروع/وسوم/مستودعات، كتابة أسرار في المستودع.
6. **الأسرار من `$ENV_VAR` فقط** — لا تُطبع، لا تُكتب في ملفات، لا تُوضع في URLs.

## 4. الذاكرة طويلة المدى (Mem0 MCP)

### 4.1 الفكرة

**بدون Mem0**: كل جلسة تبدأ من الصفر.
**مع Mem0**: الوكيل يتذكر القرارات، التفضيلات، السياق — عبر الجلسات والأدوات
(Claude Code, Cursor, Codex) لأن الذكريات مربوطة بمعرّف المستخدم/الوكيل لا بالأداة.

### 4.2 متى تستخدم `search_memories`

- **في بداية كل جلسة**: "هل عملنا على هذا من قبل؟"
- **عند تبديل السياق**: "هل هناك قيود معروفة؟"
- **قبل مهمة جديدة**: "هل هناك دروس مستفادة؟"

### 4.3 متى تستخدم `add_memory`

- **بعد إتمام مهمة**: احفظ الدروس.
- **عند اتخاذ قرار معماري**: احفظ القرار وسببه (مثال: "استخدمنا pypdfium2 بدل PyMuPDF بسبب الترخيص").
- **عند اكتشاف قيد**: احفظه (مثال: "لا GPL/AGPL في نواة MIT").

### 4.4 ما يُحفظ / ما لا يُحفظ

| يُحفظ | لا يُحفظ |
|-------|----------|
| القرارات المعمارية | الأسرار (مفاتيح، كلمات مرور، رموز جلسات) |
| التفضيلات | بيانات شخصية حساسة |
| الدروس المستفادة | محتوى مؤقت غير مهم |
| القيود الصارمة | — |

### 4.5 التثبيت (اختياري لكل أداة)

```bash
npx mcp-add \
  --name mem0-mcp \
  --type http \
  --url "https://mcp.mem0.ai/mcp" \
  --clients "claude code,cursor"
# أو يدوياً: خادم http على https://mcp.mem0.ai/mcp مع MEM0_API_KEY من البيئة
# بديل محلي بالكامل (بلا سحابة): OpenMemory MCP
```

للتحقق من أن الذاكرة تعمل فعلاً عبر الجلسات:

```bash
export MEM0_API_KEY="m0-..."
python3 scripts/test_mem0_memory.py
```

## 5. Harness في الممارسة

### 5.1 سيناريو: جلسة جديدة

```bash
./init.sh                                # 1. بوابة الدخول
cat session-handoff.md                   # 2. أين توقفنا؟
# (في الوكيل) search_memories(query="<المشروع> context")
git checkout -b feat/<task>              # 3. فرع جديد — لا عمل على main
# ... التنفيذ ...
./scripts/verify.sh                      # 4. بوابة الجودة قبل الالتزام
git commit -m "feat: ..."                # 5. التزام مستقل
python3 scripts/session-handoff.py --note "أنجزت X" --next "ابدأ بـ Y"
git add progress.md session-handoff.md && git commit -m "chore: session handoff"
git push origin feat/<task>              # 6. فرع فقط — ثم PR مسودة للمالك
```

### 5.2 سيناريو: فشل بوابة

```bash
./scripts/verify.sh
# ❌ pytest فشل
# STOP — لا تكمل: اقرأ المخرج الخام، أبلغ المالك في التقرير بـ REASON:،
# لا تُصلح "بسرعة" خارج نطاق المهمة.
```

## 6. أنماط الفشل المعروفة

| النمط | السبب | التجنّب |
|-------|-------|---------|
| "phantom bug" | بناء على نصوص معروضة (قد تُشوَّه) | اقرأ البايتات (`od -c`) |
| اختلاق مصادر | رغبة في إكمال الوثيقة | كل ادعاء = رابط أو يُحذف |
| تدمير بيانات | تطبيع مدمِّر | التطبيع للمطابقة فقط، لا للنص المعروض |
| تجاوز بوابة | "أصلح بسرعة" | STOP فوراً |
| نسيان السياق | لا ذاكرة | Mem0 في بداية الجلسة |

## 7. الفرق عن الأنماط الأخرى

| | Prompt Engineering | RAG | Agent Frameworks | **Harness** |
|--|--------------------|-----|------------------|-------------|
| النطاق | سؤال واحد | معرفة | تطبيقات وكلاء | **دورة حياة التطوير** |
| الحالة | لا | استرجاع | حسب الإطار | **حالة صريحة ملفية** |
| التحقق | لا | لا | حسب الإطار | **بوابات إجبارية** |
| الزمن | الجلسة | الجلسة | production | **عبر الجلسات** |

## 9. الخلاصة

الـ Harness ليس مجموعة قواعد — هو طريقة تفكير:

> بدلاً من "أعطِ النموذج سؤالاً جيداً"، نبني بيئة عمل تحدد كيف يعمل الوكيل،
> متى يتوقف، وكيف يسلّم للجلسة التالية.

- **بدون Harness**: كل جلسة معركة جديدة.
- **مع Harness**: كل جلسة خطوة في مسار.

الاستثمار: ساعة إعداد = ساعات موفّرة على كل جلسة.

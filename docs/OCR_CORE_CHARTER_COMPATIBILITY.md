# OCR Core ↔ Marathon charter compatibility

**Purpose.** Keep `config/marathon_ocr_rules.yaml` (rule `R16.params.require_visual_evidence`)
honest about what the pinned `ocr-core` release can actually do.

**Machine-readable manifest:** `docs/ocr_core_charter_compatibility.json`
(generated by inspecting the engine source of each ocr-core release).

**Current verified state**

| Item | Value |
|---|---|
| Pin in `requirements.txt` | see `marathon-ocr-core @ git+...@<tag>` |
| Charter rule | `R16.params.require_visual_evidence` |

**Rule.** A charter may require the visual-evidence gate **only** if the pinned release
implements it (`engine_implements_visual_evidence_gate: true`). Otherwise the flag is
inert and any label derived from word-ratio cleanliness is *not* evidence-grounded.

**Enforced by** `tests/test_charter_engine_compat.py` (offline, deterministic).

**Rollback.** Both the config value and the pin must move together: revert the config
boolean and the `requirements.txt` pin in the same commit.
